# 拡充計画 — 20件から120件規模へ

この文書は実装の引き継ぎ用です。フェーズ0から順に進めてください。

## 1. 現状の診断

### 1-1. 最大の問題:プレビューとコピー用コードが別実装

1つのアニメーションが、2つの独立した実装を持っています。

| 用途 | 場所 | 例(CSS-001 バウンドボール) |
|---|---|---|
| コピーされるコード | `data/animations.ts` の `css` 文字列 | `.bounce-ball { background: #ff5b45; animation: bounce 0.8s ... }` |
| 画面に表示される動き | `styles.css` の `.demo-*` ルール | `.demo-bounce-ball { border: 2px solid var(--ink); background: var(--coral); box-shadow: ...; animation: demo-bounce var(--duration) ... }` |

両者はすでに一致していません。表示側だけに `border` と `box-shadow` があります。
つまり「見た目を気に入ってコピーしたのに、貼り付けたら違うものが出る」状態が、
20件の時点で発生しています。

さらに、1件追加するのに4ファイルの編集が必要です。

1. `types.ts` の `PreviewKind` にリテラルを追加
2. `data/animations.ts` にデータを追加
3. `components/AnimationStage.tsx` の `switch` に分岐を追加
4. `styles.css` に `.demo-*` ルールと `@keyframes demo-*` を追加
5. `AnimationStage.tsx` の `baseDurations` に秒数を追加(実質5箇所)

120件に増やすと編集箇所は約600に達し、表示とコピー用コードの乖離は確実に拡大します。
**件数を増やす前に、ここを単一のソースへ統合します。**

### 1-2. 件数増加で顕在化する問題

| 問題 | 現状 | 120件での影響 |
|---|---|---|
| 同時再生 | 20件が常時アニメーション | 120件が常時再生。描画負荷とバッテリー消費が実用に耐えない |
| 視野外の制御 | `content-visibility` / `IntersectionObserver` ともに不使用 | 画面外のカードも再生され続ける |
| 速度制御の結合 | `--duration` 変数に依存し、`baseDurations` に秒数を二重管理 | 追加のたびに手入力が増え、コピー用コードとずれる |
| 分類の粒度 | カテゴリー6種のみ | 1カテゴリー20件で一覧性が失われる |

### 1-3. 実用性の観点で不足しているもの

- **`prefers-reduced-motion` 対応がコピー用コードに含まれない。**
  `styles.css:333` にサイト全体を止める指定はありますが、利用者がコピーするコードには
  一切含まれません。このライブラリから貼り付けたコードは、そのままではアクセシビリティ要件を
  満たさないことになります。
- **トリガーの情報がない。** 現在の20件はほぼすべて無限ループです。実務で必要になる
  「ホバーしたとき」「チェックしたとき」「表示されたとき」といった発火条件を持つ動きが
  ほぼありません。また、探すための軸も存在しません。
- **性能特性の情報がない。** `transform` / `opacity` のみで動くもの(合成のみで完結)と、
  `width` や `top` を動かすもの(レイアウト再計算が発生)が区別されていません。

## 2. 分類の設計

### 2-1. 方針:1軸から3軸へ

現在のカテゴリー6種は、用途(登場・退場)と対象(文字、UIパーツ)と目的(ローディング)が
同一の軸に混在しています。120件では破綻するため、独立した3軸に分けます。

### 2-2. 軸1:用途カテゴリー(単一選択・10種)

| カテゴリー | 内容 | 目標件数 |
|---|---|---|
| 登場・退場 | 要素の出現と消滅 | 12 |
| ローディング・進捗 | 待機表示、進捗表現 | 12 |
| フィードバック | 成功、失敗、警告への反応 | 10 |
| ボタン・リンク | 押下可能な要素の反応 | 12 |
| フォーム入力 | 入力欄、チェック、トグル、検証 | 12 |
| ナビゲーション・開閉 | 開閉、遷移、メニュー、ツールチップ | 12 |
| 文字・テキスト | 文字単位の表現 | 10 |
| 注目・バッジ | 通知、強調、誘導 | 8 |
| 背景・装飾 | 環境的な動き | 8 |
| スクロール連動 | スクロール位置に追従する動き | 8 |

### 2-3. 軸2:トリガー(単一選択・5種)

実務での検索軸として、この軸が最も効きます。

| トリガー | 意味 |
|---|---|
| ループ | 常時再生。読み込み表示、装飾など |
| 一度だけ | マウント時や表示時に1回だけ再生 |
| ホバー | `:hover` / `:focus-visible` で発火 |
| 状態変化 | `:checked`、`[aria-expanded]`、クラス付け替えで発火 |
| スクロール | `animation-timeline` またはビューポート交差で発火 |

### 2-4. 軸3:タグ(複数選択・自由語)

既存どおり自由語とします。プロパティ名(`transform`、`clip-path`)、
モチーフ(ボタン、カード)、技法(`steps`、`@property`)などを付けます。

## 3. データモデルの変更

`types.ts` を次の形に変更します。

```ts
export type AnimationCategory =
  | '登場・退場' | 'ローディング・進捗' | 'フィードバック'
  | 'ボタン・リンク' | 'フォーム入力' | 'ナビゲーション・開閉'
  | '文字・テキスト' | '注目・バッジ' | '背景・装飾' | 'スクロール連動'

export type Trigger = 'ループ' | '一度だけ' | 'ホバー' | '状態変化' | 'スクロール'
export type Difficulty = 'かんたん' | 'ふつう' | 'しっかり'
export type Cost = '軽い' | '注意'

export interface AnimationItem {
  id: string
  referenceId: string
  title: string
  description: string
  category: AnimationCategory
  trigger: Trigger
  tags: string[]
  difficulty: Difficulty
  /** 軽い = transform / opacity / filter のみ。注意 = レイアウトや塗りを動かす */
  cost: Cost
  html: string
  css: string
  /** prefers-reduced-motion: reduce のときの代替。コピー用コードに連結される */
  reducedMotion: string
  /** 対応状況に注意が要る場合のみ記載(animation-timeline など) */
  browserNote?: string
  note?: string
}
```

削除するもの:`PreviewKind`(型ごと不要になります)、`preview` フィールド。

## 4. アーキテクチャの変更

### 4-1. 単一ソース化

プレビューを `html` / `css` 文字列そのものから描画します。
表示されている動きと、コピーされるコードが、定義上一致します。

分離の手段は **Shadow DOM** を使います。

```tsx
// AnimationStage.tsx の中核。既存の switch 文と baseDurations は全削除
const host = useRef<HTMLDivElement>(null)

useEffect(() => {
  const root = host.current!.shadowRoot ?? host.current!.attachShadow({ mode: 'open' })
  root.innerHTML = `<style>${css}</style>${html}`
}, [css, html, replayKey])
```

Shadow DOM を選ぶ理由:

- クラス名と `@keyframes` 名の衝突が、命名規約ではなくブラウザーによって防止されます。
  120件を手書きする以上、規約の遵守に依存する設計は成立しません
- テーマ用のカスタムプロパティは Shadow 境界を継承して届くため、背景切り替えは現状のまま動きます
- iframe と違い、生成コストがほぼありません

`html` / `css` は作者が書いた静的な文字列で、外部入力ではありません。
`innerHTML` の使用はこの前提のもとで許容します。**利用者入力を流し込む経路を作らないでください。**

### 4-2. 速度と再生制御を Web Animations API へ

`--duration` 変数による結合をやめます。コピー用コードには実際の秒数(`0.8s`)を
リテラルで書き、再生制御は実行時に行います。

```ts
const anims = host.current!.shadowRoot!.getAnimations()
anims.forEach((a) => {
  a.playbackRate = speed
  paused ? a.pause() : a.play()
})
```

`ShadowRoot.getAnimations()` を使う点に注意してください。
ホスト要素側の `getAnimations({ subtree: true })` は Shadow 境界を越えません。

これにより `baseDurations`(20行の秒数の二重管理)が不要になります。

### 4-3. 描画負荷への対処

120件が同時再生される状態を避けます。

- カードに `content-visibility: auto` と `contain-intrinsic-size` を指定
- `IntersectionObserver` で視野外に出たカードの `Animation` を `pause()`、
  再交差時に `play()`

4-2 で `Animation` オブジェクトを扱える状態になっているため、追加実装はわずかです。

### 4-4. reduced-motion をコピー用コードに含める

`reducedMotion` フィールドの内容を、コピーされる CSS の末尾に連結します。

```css
/* 例:CSS-001 のコピー結果末尾 */
@media (prefers-reduced-motion: reduce) {
  .bounce-ball { animation: none; }
}
```

あわせて `styles.css:333` の全体停止指定を見直します。
現状はアニメーション図鑑そのものを止めてしまうため、サイトの装飾部分に限定し、
プレビュー内は各アニメーション自身の `reducedMotion` に委ねる形にします。

## 7. 検証

### 7-1. データ検証スクリプト(フェーズ3で追加)

`scripts/check-data.mjs` を追加し、`package.json` に `"check:data"` として登録します。
`npm run build` の前段に組み込み、GitHub Actions でも実行されるようにします。

検査内容:

1. `id` の重複がないこと
2. `referenceId` が `CSS-NNN` 形式で、重複がないこと
3. 公開済みの `CSS-001`〜`CSS-020` の `id` と `referenceId` の対応が変わっていないこと
4. `category` と `trigger` が定義済みの値であること
5. `html` / `css` / `reducedMotion` が空でないこと
6. `css` に `animation` または `transition` が1つ以上含まれること
7. `css` 内の `@keyframes` 名が、その項目の `css` 内から参照されていること(記述漏れの検出)

これが120件を支える唯一のガードです。件数が増えるほど手動確認は現実的でなくなります。

### 7-2. 各フェーズの目視確認

```
npm run dev
```

- フェーズ1完了時:20件すべてが以前と同じ見た目で動くこと。
  カード上の表示と、コード欄の内容が一致していること
- フェーズ2完了時:速度スライダーと停止ボタンが効くこと。
  画面外へスクロールしたカードが停止すること(DevTools の Performance で確認)
- 各追加フェーズ:追加分が全カテゴリー・全トリガーの絞り込みに正しく現れること

## 8. 今回やらないこと

| 項目 | 理由 |
|---|---|
| vite 5 → 8 の更新 | `npm audit` の指摘は開発サーバー限定で、公開物に影響しません。件数拡充とは無関係です |
| アニメーションのコード生成UI(色や秒数のGUI編集) | 需要が確認できていません。まず件数を揃え、要望が出てから検討します |
| 検索のあいまい一致・かな漢字対応 | 現在の部分一致で120件は捌けます。実際に探せない場面が出てから対応します |
| カテゴリー別のページ分割 | ハッシュによる直リンクの仕組みと衝突します。絞り込みで足ります |
